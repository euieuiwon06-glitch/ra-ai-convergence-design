# 02. 사용자 및 사례 조사 — 보완 내용 (C. 음성 기반 · 소리 내어 외우는 한국사)

목표: 기존 서비스·연구 사례를 구체적인 출처와 사용 기술까지 조사하고, 그 한계에서 이 앱이 왜 "말하게 하고 키워드로 채점하는" 방향을 잡았는지 스토리로 정리한다.

| 서술형 자동채점 기술 검증 | c-rater, ETS — Leacock & Chodorow, *Computers and the Humanities*, 2003 | 정답에 담겨야 할 **개념(concept) 목록**을 정의하고, 형태소 분석·동의어·대명사 참조·술어논항 구조로 응답에 그 개념이 있는지 판정 | 개념 사전과 동의어 목록을 사람이 미리 구축해야 함. 단순 문자열 일치로는 부족하다는 것을 이 시스템 자체가 보여줌 |

> 확인해서 채워 넣을 것: 각 앱의 **확인일**(예: 2026.08.○○ 기준), 트루토리 앱의 정확한 개발사 표기, CLOVA Speech Recognition의 키워드 부스팅(boostings) 지원 여부.

## 표2. 학습·평가 도메인 선행 연구 (직접 관련)

| 이름·출처 | 연구 내용 | 발견 / 시사점 |
|---|---|---|
| Roediger & Karpicke, *Psychological Science*, 2006 | 대학생에게 산문 지문을 학습시킨 뒤 ①반복 읽기 ②반복 시험(피드백 없음) 조건으로 나눠 5분·2일·1주 뒤 파지 검사 | 5분 뒤에는 반복 읽기가 더 나았지만, 지연 검사에서는 시험 조건이 크게 앞섬. 특히 **반복 읽기는 "기억할 수 있다는 자신감"만 올렸다.** → 눈으로 읽는 복습은 실력이 아니라 확신을 키운다는 직접 근거 |
| Karpicke, Butler & Roediger, *Memory*, 2009 | 대학생 **177명** 설문. 실제 공부할 때 쓰는 전략을 자유응답 + 강제선택으로 조사 | 대다수가 노트·교재 반복 읽기를 선택했고 자가 테스트를 하는 학생은 소수. 저자들은 이를 **"유능감의 착각(illusions of competence)"** 으로 설명 → 사용자가 스스로 인출 연습을 하지 않으므로, 앱이 인출을 강제해야 하는 근거 |
| MacLeod et al., *JEP: LMC*, 2010 | 8개 재인 실험으로 소리 내어 읽은 단어와 눈으로만 읽은 단어의 기억을 비교 | 소리 내어 산출한 항목이 더 잘 기억됨(**production effect**). 산출된 항목이 구별성(distinctiveness)을 얻기 때문 → "말하게 한다"는 인터랙션 자체가 학습 장치가 되는 근거 |
| Slamecka & Graf, *JEP: HLM*, 1978 | 주어진 단어를 읽게 한 조건과 스스로 만들어내게 한 조건 비교 | 스스로 생성한 항목이 더 오래 남음(**generation effect**) → 정답을 먼저 보여주면 안 되고, 카드를 감춘 뒤 먼저 말하게 해야 하는 순서의 근거 |
| Leacock & Chodorow, *Computers and the Humanities*, 2003 | ETS의 단답형 자동채점 엔진 c-rater를 NAEP와 인디애나 주 단위 평가에 적용 | 개념 기반 자동채점이 **사람 채점자와 약 84% 일치**. 단답 서술을 기계가 채점하는 것이 실무에서 성립한다는 근거. 동시에 "단순 문자열 매칭이 아니다"라고 명시 → 형태소·동의어 처리가 필요하다는 경고 |
| Burrows, Gurevych & Stein, *IJAIED*, 2015 | 단답형 자동채점(ASAG) 연구 80여 편, 시스템 35종을 5개 시대로 정리한 리뷰 논문 | 채점 방식이 ①정답과의 문자열/개념 일치 ②말뭉치 기반 의미유사도 ③지도학습 분류 세 갈래로 갈림. 학습 데이터가 없는 소규모 프로젝트에서는 **개념·키워드 일치 방식이 현실적 선택**이라는 지도 |

> 참고: Karpicke et al.(2009)의 "반복 읽기 선호" 결론은 Kuhbandner & Emmerdinger(*Memory*, 2019)가 설문 문항의 조작적 정의를 문제 삼아 재검증한 바 있다. 결론이 완전히 뒤집힌 건 아니지만, "학생들이 자가 테스트를 잘 안 한다"는 주장을 인용할 때 단정하지 말고 경향으로 쓸 것.

## 스토리 흐름 (프로젝트 시작 계기)

| 단계 | 발견 | 결론 |
|---|---|---|
| 1. 시장 공백 확인 | 한능검 앱은 전부 객관식이고, 플래시카드 앱(Anki)은 채점을 사용자 본인에게 맡긴다. **서술을 시키고 그 서술을 채점해주는 자리가 비어 있음** | "고르는 앱"과 "스스로 채점하는 앱" 사이에 자리가 있다 |
| 2. 인출을 강제해야 하는 이유 확인 | Roediger & Karpicke(2006) — 반복 읽기는 파지가 아니라 자신감만 올림. Karpicke et al.(2009) — 학생 177명 중 자가 테스트를 하는 사람은 소수 | 사용자가 알아서 인출하기를 기다리면 안 되고, 앱이 인출을 강제해야 한다 |
| 3. 인출 방식 결정 근거 확인 | MacLeod et al.(2010) 발화 효과 + Slamecka & Graf(1978) 생성 효과 | 타이핑이 아니라 **소리 내어 말하게** 하고, 정답은 말한 **뒤에** 공개한다 |
| 4. 기술 실현 가능성 확인 | CLOVA Speech Recognition으로 마이크만으로 한국어 발화를 텍스트화 가능. 기존 앱들도 이미 음성을 쓰지만 TTS(듣기) 방향 | 마이크 하나로 구현 가능하며, 아직 아무도 STT(말하기) 방향으로 쓰고 있지 않다 |
| 5. 채점 가능성 확인 | c-rater가 개념 기반 채점으로 사람과 84% 일치. Burrows et al.(2015)는 학습 데이터 없는 환경에서 개념·키워드 일치 방식이 유효하다고 정리 | 서술 채점은 LLM 없이도 규칙만으로 성립한다 |

여기까지가 "왜 말하게 하고, 왜 채점이 가능한가"에 대한 결론이다. 그런데 정작 **"말한 내용을 무엇으로 판정할 것인가"** 는 아직 정하지 않은 상태였다. 표1의 사례들이 저마다 다른 방식으로 정답 여부를 가리고 있었기 때문에, 이 방식들을 직접 비교해서 채점 방식부터 결정할 필요가 있었다.

## 표3. 인출·채점 방식 비교 — 왜 "발화 + 키워드 규칙 채점"인가

| 방식 | 대표 사례 | 무엇을 측정하나 | 필요 조건 | 한계 |
|---|---|---|---|---|
| 객관식 정답 대조 | 한능검 기출 앱 (트루토리 등) | 정답 선지를 고를 수 있는가 | 문제 DB | 보기가 힌트가 됨. 떠올린 건지 알아본 건지 구분 불가. 서술 능력은 아예 측정 대상 밖 |
| 자가 평가 (카드 뒤집기) | Anki (Again/Hard/Good/Easy) | 본인이 "안다"고 느끼는가 | 카드 덱 | 채점 주체가 학습자 본인. 유능감의 착각을 그대로 통과시킴 |
| 발음·문장 일치 평가 | 클래스카드 스피킹, ELSA Speak | 정해진 문장을 정확히/유창하게 발음했는가 | 마이크 + 기준 문장 | 기준 문장이 미리 있어야 함. 자기 말로 바꿔 설명하면 오답 처리됨 |
| 의미 유사도 채점 | ASAG 연구 계열 (임베딩·문장 유사도) | 모범답안과 의미가 얼마나 가까운가 | 사전학습 모델 + 임계값 튜닝 | 점수가 왜 그렇게 나왔는지 설명이 안 됨. 같은 답변이 다르게 채점될 수 있음 |
| LLM 채점 | 최근 자동채점 연구 계열 | 답변 전반을 언어모델이 평가 | API 비용 + 네트워크 | 같은 답변에 다른 판정이 나올 수 있고, 어떤 근거로 통과인지 사용자에게 설명하기 어려움. 지연·비용도 발생 |
| **개념·키워드 규칙 채점** | c-rater(ETS), **본 프로젝트** | 답변에 **핵심 개념이 실제로 들어 있는가** | 문항별 키워드 세트 + 매칭 규칙 | 키워드 세트를 사람이 정의해야 하고, 어순·인과 설명은 평가하지 못함. 문자열 일치만으로는 부족해 형태소·동의어 처리를 직접 보완해야 함 |

표1의 CLOVA Speech Recognition(마이크 하나로 한국어 발화 → 텍스트)이 "말하게 한다"가 기술적으로 가능하다는 근거였고, c-rater(개념 기반 채점, 사람과 84% 일치)가 "그 말을 채점할 수 있다"는 근거였다. 두 사례 모두 별도 학습 데이터 없이 규칙과 사전만으로 동작한다는 점에서, 학기 단위 프로젝트 규모에 맞는 방식이었다.

다만 c-rater가 "단순 문자열 매칭이 아니다"라고 못 박은 부분이 이 프로젝트의 남은 숙제이기도 하다. 키워드를 문자열 포함 여부로만 세면 사건 이름 하나가 키워드 여러 개를 동시에 채우는 문제가 생기는데, 이 부분은 07·10장에서 다시 다룬다.

## 표4. 기존 사례별 한계 → 어떻게 극복했나

| 기존 사례 | 뭐가 문제였나 | 이 앱은 어떻게 다른가 |
|---|---|---|
| 한능검 기출 앱 (객관식) | 보기를 보고 고르는 구조라 인출이 일어나지 않음 | 보기를 아예 주지 않고, 사건 이름만 3초 보여준 뒤 감추고 설명하게 함 |
| 한능검 기출 앱 (음성 듣기형) | 음성을 쓰지만 기기가 읽어주는 방향뿐. 사용자는 계속 수동 | 음성의 방향을 뒤집음. 사용자가 말하고 기기가 받아 채점함 |
| Anki | 맞았는지 틀렸는지를 본인이 판정 → 착각을 거르지 못함 | 채점 주체를 시스템으로 옮김. 키워드 매칭 개수로 판정하므로 본인 느낌이 개입할 수 없음 |
| 클래스카드 스피킹 | 정해진 문장을 그대로 말해야 통과. 자기 말로 바꾸면 오답 | 문장 일치가 아니라 **핵심어 포함 여부**로 봄. 표현이 달라도 핵심 개념이 들어 있으면 인정 |
| ELSA Speak | 발음만 보고 내용은 안 봄 | 발음은 안 보고 내용만 봄. 억양·속도와 무관하게 서술 내용으로 판정 |
| 의미 유사도 · LLM 채점 | 점수 근거를 설명하기 어렵고, 같은 답에 다른 결과가 나올 수 있음 | 규칙 기반이라 같은 답변은 항상 같은 결과. 어떤 키워드가 맞았고 뭐가 빠졌는지 그대로 보여줌 |
| c-rater | 개념 사전을 사람이 직접 구축해야 함 (주관 개입) | 개념(키워드)을 손으로 고르지 않고 원문에서 TextRank로 계산해 뽑고, 산출 근거를 표로 남김 (→ 03장) |

이렇게 채점 방식(표3)과 사례별 극복(표4)까지 정리하고 나면, "그래서 정답 키워드를 구체적으로 어떻게 뽑을 것인가"로 다음 페이지(03. 정답 키워드 선정 및 근거 도출)로 이어진다.

## 슬라이드 배치 제안 (p4)

지금 p4는 3단(기존 서비스 / 문헌 / 조사 결과 정리)인데, 표가 4개로 늘어나면 한 장에 안 들어간다. **p4를 두 장으로 분리**할 것.

**p4 — 사례 조사 · 문헌 조사**
- 좌 60%: 표1 (기존 서비스·사례 조사) — 이름·출처 / 사용 기술 / 한계 3열
- 우 40%: 표2 (선행 연구) — 서지사항은 각 행 하단에 회색 작은 글씨로
- 하단 띠: 스토리 흐름 5단계를 가로 화살표로

**p4-1 — 채점 방식 비교 · 차별점 도출**
- 상단: 표3 (인출·채점 방식 비교) — 마지막 행(본 프로젝트)만 포인트 컬러로 강조
- 하단: 표4 (사례별 한계 → 극복) — 좌 "뭐가 문제였나" / 우 "이 앱은 어떻게 다른가" 대비 배치
- 우하단 마무리 한 줄: `고르는 앱도, 스스로 채점하는 앱도 아닌 — 말하게 하고 그 말을 규칙으로 채점하는 앱`

**주의**: 슬라이드가 한 장 늘어나면 전체 15장 → 16장이 되므로, 앞서 정리한 p15 교체(결론 장표 → 실사용 캡처)와 묶어서 처리하면 장수를 유지할 수 있다. 푸터 `n / 15` 하드코딩 여부 확인 필요.
