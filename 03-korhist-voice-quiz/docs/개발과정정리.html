소리 내어 외우는 한국사 — 개발 과정 정리

음성 기반 인터랙티브 한국사 암기 퀴즈 · 프로토타입 제작 기록
한 줄 소개. 사건 이름이 화면에 잠깐 나타났다 사라지면, 사용자가 소리 내어 설명하고, 그 말을 AI가 글자로 바꿔 핵심어가 들어갔는지로 정답을 판정하는 앱입니다. 눈으로 읽기만 하는 암기보다, 직접 소리 내어 답을 꺼낼 때 기억이 더 오래 남는다는 발화 효과·생성 효과 이론에 근거했습니다.

1. 화면(앱)은 어떻게 만들었나

  • Figma 시안을 바탕으로 HTML·CSS·JavaScript만으로 앱 화면을 그대로 구현했습니다. (별도 설치 없이 브라우저로 실행)
  • 스플래시 → 홈 → 단원 선택 → 카드 노출 → 듣는 중 → 피드백(5문항 반복) → 결과 요약, 그리고 해설·원문 팝업까지 모든 화면을 만들었습니다.
  • 진행 흐름은 타이머로 자동 제어됩니다: 카드가 3초간 보이고 사라지면 마이크가 켜지고, 말을 마친 뒤 2초간 조용하면 자동으로 채점합니다.
  • 결과에 따라 완전정답 / 통과 / 부분정답 / 모름 네 가지 피드백 화면이 색깔과 함께 다르게 나옵니다.
  • 이후 학습 통계 화면도 추가했습니다. 총 학습 횟수·누적 정답률·연속 학습일과, "자주 놓치는 핵심어 Top3"를 실제 학습 기록(브라우저 저장)으로 보여줍니다.

2. 채점은 어떻게 하나 — "AI가 판단"이 아니라 "규칙으로 판정"

핵심 원칙: 정답/오답 판단에 AI(LLM)를 쓰지 않습니다. AI는 "음성 → 글자" 변환에만 쓰고, 맞고 틀림은 정해진 키워드가 답변에 들어있는지 개수를 세는 단순 규칙으로만 정합니다.
  • 문항마다 정답 키워드 5개가 정해져 있습니다.
  • 사용자의 답변(글자로 변환된 것)에 그 키워드가 몇 개 들어있는지 셉니다.
  • 5개 다 맞으면 완전정답, 3개 이상이면 통과, 1~2개면 부분정답, 0개면 모름.
  • 덕분에 "사건 이름만" 말해서는 통과되지 않고, 연도·계기·내용을 실제로 설명해야 통과합니다.

3. 핵심 키워드를 사람이 아니라 "알고리즘"으로 뽑기

처음에는 키워드를 손으로 골랐는데, 주관적이라는 지적이 있었습니다. 그래서 객관적인 자동 추출로 바꿨습니다.

  • 원문 확보: 한국사능력검정시험 공식 자료 기반의 사건별 설명 문단을 준비.
  • 형태소 분석: 한국어 분석기(kiwipiepy)로 문장에서 명사만 추출.
  • TextRank: 단어들이 함께 등장하는 관계를 그래프로 만들어 중요한 단어에 점수를 매김. (구글 페이지랭크와 같은 원리, AI 아님)
  • 공통 일반어 억제(IDF): '조선·일본'처럼 여러 사건에 다 나오는 흔한 단어는 점수를 낮춰서 걸러냄.
  • 인물·연도 포함 규칙: 학습에 꼭 필요한 연도와 핵심 인물(예: 김옥균·전봉준)은 규칙적으로 포함.

이 과정을 한 번 실행한 결과와 근거를 핵심키워드_추출근거표.xlsx로 남겨, "왜 이 키워드가 뽑혔는지" 객관적으로 설명할 수 있게 했습니다.

4. 음성 인식(STT)은 어떻게 붙였나

  • 1차: 별도 설치·비용 없이 바로 되는 브라우저 기본 음성 인식(Web Speech API)으로 구현.
  • 2차(실제 서비스용): 정확도와 완성도를 위해 네이버 CLOVA 음성 인식을 연동.
  • 두 방식은 자동으로 전환되고, 마이크를 못 쓰는 환경에서는 키보드 입력으로도 전체 흐름이 그대로 됩니다.

5. API 권한 받기 & 백엔드 연동 (상세)

왜 백엔드가 필요했나

  • CLOVA 음성 인식은 브라우저에서 직접 부를 수 없고, 무엇보다 비밀 키를 앱 코드에 넣으면 안 됩니다(유출 위험).
  • 그래서 중간 서버를 하나 두어, 앱은 서버에만 말을 걸고 서버가 키를 들고 CLOVA를 호출하도록 했습니다.

API 권한(키) 받은 과정

  • 네이버 클라우드 플랫폼(NCP)에서 CLOVA Speech Recognition 서비스를 신청.
  • 인증 정보에서 API 키 2개(Key ID / Key)를 발급받음.
  • 이 키는 앱이 아니라 서버(Supabase)의 비밀 저장소(시크릿)에 등록 → 사용자에게 절대 노출되지 않음.

중간 서버(백엔드) 구성 — Supabase Edge Function

기존에 다뤄본 Supabase를 백엔드로 활용했습니다. 작은 함수 하나(clova-stt)를 올려 "음성을 받아 CLOVA에 넘기고 글자만 돌려주는" 역할만 맡겼습니다.

기술적으로 신경 쓴 점

  • 오디오 포맷 문제 예방: 브라우저 기본 녹음(webm)을 CLOVA가 거부할 수 있어, 앱에서 직접 16kHz WAV로 변환해 보내도록 만들었습니다.
  • 보안: 키는 서버 시크릿에만 저장. 앱 설정 파일에는 함수 주소만 넣습니다.
  • 안전장치: 서버·네트워크 오류가 나면 자동으로 키보드 입력 모드로 넘어가 테스트가 끊기지 않습니다.
  • 실제 연결 검증: 짧은 테스트 음성을 실제로 함수에 보내 정상(200) 응답을 확인했습니다.

6. 실행 & 공유 방법

  • 압축을 풀고 index.html을 더블클릭하면 바로 열립니다(가장 간단). 마이크가 막히면 "키보드로 답하기"로 진행.
  • 마이크까지 쓰려면 앱 실행.bat으로 실행(로컬 서버 자동 실행 + 브라우저 자동 열기).
  • 중간에 문항마다 권한을 다시 묻던 문제도, 시작할 때 한 번만 권한을 받고 마이크를 계속 유지하도록 고쳤습니다.

정리. ① Figma 시안을 실제 동작하는 앱으로 구현했고, ② 채점은 AI가 아닌 키워드 규칙으로 처리했으며, ③ 그 키워드는 형태소분석+TextRank 알고리즘으로 객관적으로 뽑았고, ④ 음성 인식은 Supabase 중간 서버를 통해 네이버 CLOVA와 안전하게(키 비노출) 연동했습니다.
