# 04 · 스터디카페 리뷰 챗봇

**리뷰(텍스트) 기반 UX 분석 및 UI 디자인**

"시험기간에도 조용해?"처럼 궁금한 걸 물으면, 실제 리뷰를 근거로 답하고 **의견이 갈리면 긍정·부정 비율과 리뷰 원문을 함께 보여주는** Q&A 챗봇입니다.
단순히 요약해 주는 봇이 아니라, 방문할지 판단을 돕는 도구를 목표로 했습니다.

- 🖥️ **웹 프로토타입:** https://euieuiwon06-glitch.github.io/ra-ai-convergence-design/04-review-chatbot/demo/

| 항목 | 내용 |
|---|---|
| 대상 매장 | 단디스터디카페 전농점 (네이버 지도 리뷰) |
| 타깃 | 스터디카페 방문 전 정보를 확인하려는 사용자 |
| 카테고리 | 혼잡도 / 소음 / 시설 / 몰입환경 / 운영시간 |
| 기술 | React 19 + Vite (프론트), FastAPI + SQLite (백엔드), GPT · Claude · Gemini 교차검증 |

## 문제 정의와 차별점

방문 전에 리뷰를 찾아봐도 리뷰가 길고 흩어져 있어 "언제 붐비는지", "시설이 어떤지" 같은 실질적인 정보를 얻기가 번거롭습니다.
Google Places AI 요약이나 야놀자 리뷰 같은 기존 서비스는 대부분 요약·추천형입니다. 이 챗봇은 근거를 함께 제시한 의견 요약이 더 유용하다는 연구(RATION, 2024)를 바탕으로, **질문형 Q&A + 근거 원문 + 의견 갈림 판단**으로 차별화했습니다.

## 답변 상태 (6개)

| 상태 | 조건 |
|---|---|
| 대기 | 질문 입력 전 |
| 로딩 | 질문 전송 직후 |
| 확실 답변 | 긍정:부정이 7:3 밖 |
| 의견 갈림 | 긍정:부정이 7:3 안쪽 (정확히 70:30은 갈림 아님) |
| 정보 부족 | 관련 리뷰 조각이 3개 미만 (맥락형 질문만 해당) |
| 이해 실패 | 매칭되는 카테고리 없음 |

운영시간처럼 사실을 묻는 질문은 조각 1개로도 답하고, 혼잡도·소음·몰입환경처럼 맥락을 묻는 질문은 3개 이상이 필요합니다. 시설은 "콘센트 있어요?"(사실형)와 "청소 잘 되나요?"(맥락형)가 섞여 있어 질문 키워드로 나눕니다.

## 데이터 파이프라인

1. **수집:** 네이버 지도 리뷰를 개발자도구 콘솔로 한 번에 추출
2. **문장 분절:** "조용하고 좋은데 에어컨이 좀 세요" → 소음/긍정 + 시설/부정. 사실과 경험이 섞인 문장(시설 vs 몰입환경)도 의미 단위로 나눔
3. **레이블링:** 같은 프롬프트로 **GPT · Claude · Gemini**에 각각 분류시키고 다수결로 확정. 세 모델이 모두 다르면 판단 보류
4. **보강:** 테스트 중 "몇 시까지 해?"에 답하지 못하는 걸 발견해 운영시간 카테고리를 추가하고 약 100문장으로 확장
5. **Q&A 데이터셋:** 카테고리별 긍정·부정 수, 답변 상태, 근거 원문 예시 구성

> 교수님 피드백 반영: "누구 기준 레이블링인가"라는 질문에 답하기 위해 단일 모델 판단을 3모델 교차검증으로 바꿈

## 내 리뷰 추가하기

업로드한 리뷰도 분절하고 3모델로 교차검증합니다. 모델별 긍정 확률의 평균이 70% 이상이면 긍정, 30% 이하면 부정, 그 사이는 판단 보류로 처리합니다. 분절 결과가 모델마다 갈리면 저장하지 않고 **관리자 승인 대기**로 둡니다.
모델 하나가 실패하면 1회 재시도하고, 성공한 모델이 2개 미만이면 "지금은 분석이 어려워요"를 반환합니다.

## UI

다크 배경 `#17171C` + 민트 포인트 `#3FA57A`, Noto Sans KR, 375×812 모바일.
사용자·AI 말풍선, 확실/갈림 배지, 긍정·부정 비율 바, 원문 리뷰 아코디언, 추천 질문 칩, 네이버 지도 바로가기로 구성했습니다.

## 폴더

```
prototype/      React + Vite 소스 (src/data/qa.js 매칭 로직 · reviews.js 리뷰 데이터)
demo/           GitHub Pages용 빌드 결과
backend/        FastAPI: /chat · /reviews · /reviews/analyze, 3-LLM 다수결·분절·신뢰도, pytest
data/           리뷰 분류표(레이블링), 모델별 카테고리·톤 교차검증표(xlsx), 기준값 비율표, 추가 기능 판단 지침
docs/           진행 과정 정리
handout/        유인물 docx
slides/         강의 슬라이드
```

### 실행

```bash
# 프론트
cd prototype && npm install && npm run dev

# 백엔드
cd backend
pip install -r requirements.txt
python -m db.migrate && python -m db.seed
uvicorn app.main:app --reload --port 8000
pytest
```

3-LLM 레이블링 배치에는 `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `GOOGLE_API_KEY` 환경변수가 필요합니다.

## 한계 · 향후

- 시설과 몰입환경의 경계가 모호한 사례가 남아 있어 카테고리 정의를 더 다듬어야 함
- 크롤러는 약관 검토 전이라 스캐폴딩만 둠
- 실사용자 대상 사용성 평가 필요 (현재는 1차 자체 테스트, 분류 정확도 15/15)
