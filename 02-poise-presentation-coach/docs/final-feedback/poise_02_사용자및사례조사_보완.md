# 02. 사용자 및 사례 조사 — 보완 내용

목표: 기존 서비스·연구 사례를 구체적인 출처와 기술로 조사하고, 그 한계에서 Poise가 왜 관절 기반 감지로 방향을 잡았는지 스토리로 정리한다.

## 표1. 기존 서비스·사례 조사

| 구분 | 이름·출처 | 사용 기술 | 한계 |
|---|---|---|---|
| AI 면접 솔루션 | 뷰인터(ViewInter), 제네시스랩 — ZDNet Korea, 2023.07.27 | AI 면접관이 답변에 실시간 반응·추가질문 생성, AI 감독관이 부정행위(커닝·대리응시·화면공유) 탐지 | 채용 심사용. 지원자 본인 습관 개선 목적 아님 |
| 발표 연습 앱 | 「발표연습 – 완벽한 발표를 위한 리허설 도구」, PTINSIGHT — App Store | 녹화(화질 3단계) + 타이머·종료 알림 | AI 분석 없음. 사용자가 직접 영상 보고 스스로 판단해야 함 |
| 웹캠 자세 교정 연구 | 「웹캠 기반 거북목 판별 알고리즘을 활용한 자세 교정 반응형 헬스케어 시스템」, 박소연 외, 한국멀티미디어학회논문지, 2021 | SVM으로 턱선-어깨 거리 학습해 거북목 판별 | 감지 즉시 알림 방식. 지속 여부 고려 없이 바로 경고 |
| 관절 추정 기술 검증 | MediaPipe Pose Landmarker, Google — Google AI Edge 공식 문서 | BlazePose 기반, 카메라 1대로 33개 관절점 실시간 추정, 별도 장비 불필요 | 프레임 단위 좌표만 제공 → 지속시간 판단은 별도 로직 필요 |

## 표2. 발표 코칭 도메인 선행 연구 (직접 관련)

| 이름·출처 | 사용 기술 | 발견/시사점 |
|---|---|---|
| Presentation Trainer, TU Delft — Schneider et al., *Sensors* (MDPI), 2019 | Kinect 카메라로 자세·표정, 마이크로 음성 실시간 추적 → 텍스트/아이콘 큐로 즉시 피드백 | 실사용 테스트에서 4명이 "Stop Speaking" 같은 즉각 지시에 방해받았다고 응답. 실시간 지적이 발표 흐름을 끊는다는 걸 실증한 사례 |
| MACH (My Automated Conversation coacH), MIT Media Lab — Hoque et al., UbiComp, 2013 | 웹캠·마이크로 미소·머리제스처·음량·필러워드 분석 | 실시간 알림 대신 세션 종료 후 녹화 영상 + 정량화된 리포트 제공. Poise의 세션 리포트 구조와 동일한 접근 |
| 운동학습 이론 (Concurrent vs. Terminal Feedback), Schmidt & Wulf, *Human Factors*, 1997 | — (실험 연구) | 지속적인 실시간(concurrent) 피드백은 학습자를 피드백에 의존하게 만들어 오히려 장기 습득을 저해한다는 결과. 요약/지연 피드백이 학습에 더 유리함을 뒷받침 |

## 스토리 흐름 (프로젝트 시작 계기)

| 단계 | 발견 | 결론 |
|---|---|---|
| 1. 시장 공백 확인 | 채용평가형(뷰인터)과 단순녹화형(발표연습 앱) 사이, 연습자 본인을 위한 코칭 도구가 없음 | "혼자 연습하는 사람"을 위한 자리가 비어 있음 |
| 2. 기술 실현 가능성 확인 | MediaPipe/Kinect로 카메라 한 대만으로 자세·표정 감지 가능함 확인 | 별도 장비 없이 구현 가능하다는 확신 |
| 3. 즉시 피드백의 부작용 확인 | Presentation Trainer 실사용 테스트에서 실시간 지적에 방해받았다는 응답 다수 | 감지=즉시 알림 구조는 그대로 쓸 수 없음 |
| 4. 대안 확인 | MACH의 세션 후 리포트 방식 + Schmidt & Wulf(1997)의 지연 피드백이 학습에 유리하다는 결과 | 실시간 감지는 하되, 알림은 지속시간 기반 단계적으로 · 최종 피드백은 세션 리포트로 |

여기까지가 "언제, 어떻게 알려줄지"에 대한 결론이다. 그런데 정작 "무엇으로 감지할 것인가"는 아직 정하지 않은 상태였다. 표1의 기존 사례들은 저마다 다른 방식으로 감지하고 있었기 때문에, 이 방식들을 직접 비교해서 감지 방식부터 결정할 필요가 있었다.

## 표3. 감지 방식 비교 — 왜 관절(스켈레톤) 기반인가

| 방식 | 대표 사례 | 포착 대상 | 필요 장비 | 한계 |
|---|---|---|---|---|
| 표정·음성·시선 종합 분석 | 뷰인터(ViewInter), 제네시스랩 | 표정, 음성, 시선 반응 | 카메라+마이크 | 점수로 종합 판정만 함. 상체 흔들림 같은 신체 움직임 자체는 못 잡고, 뭘 고쳐야 하는지도 안 알려줌 |
| 음성 전용 분석 | Orai, Yoodli | 필러워드, 말속도, 억양 | 마이크만 | 신체 자세는 아예 분석 대상이 아님. 시선회피·상체흔들림 같은 시각적 습관은 원천적으로 감지 불가 |
| 웨어러블 센서 | Upright Go 2 | 등 기울기(슬라우치) 하나만 | 별도 기기 구매·부착(접착/목걸이) | 등 외 부위(고개·시선)는 못 봄, 자세 나쁘면 초반에 자주 진동해 방해됨, 부착 불편·추가 비용 |
| 단순 녹화 | 발표연습 앱(PTINSIGHT) | 없음 (영상만 저장) | 카메라 | 분석 자체가 없어 사용자가 다시 보면서 직접 판단해야 함 |
| 관절(스켈레톤) 기반 감지 | Poise | 17개 이상 관절 좌표 → 시선·고개·상체·정지까지 전신 습관 동시 추적 | 카메라 1대(폰/웹캠) | 프레임 좌표 자체는 "지금 이 순간"만 알려줘서, 지속시간 판단은 별도 로직으로 직접 보완해야 함 |

표1에서 확인한 MediaPipe Pose Landmarker(카메라 1대로 33개 관절점 실시간 추정, 별도 장비 불필요)가 바로 이 "관절 기반 감지"가 기술적으로 실현 가능하다는 근거였고, 표2의 Presentation Trainer(Kinect 필요)·MACH(음성·표정 위주)와 비교해도 일반 카메라만으로 전신 습관을 다 잡을 수 있다는 게 관절 기반의 강점이었다.

## 표4. 기존 사례별 한계 → 관절 기반 감지로 극복

| 기존 사례 | 뭐가 문제였나 | Poise는 어떻게 다른가 |
|---|---|---|
| 뷰인터 | 점수만 주고 뭘 고쳐야 할지는 안 알려줌 | 어떤 습관이 몇 초 동안 나왔는지 구체적으로 짚어줌 |
| Orai / Yoodli | 목소리만 봐서 몸 흔들림이나 시선 흐트러짐은 아예 못 봄 | 카메라로 몸 전체를 봐서, 목소리 앱이 못 보는 부분까지 잡아줌 |
| Upright Go 2 | 기기를 따로 사서 몸에 붙여야 하고, 등 하나만 보고, 진동이 너무 자주 울림 | 장비 없이 카메라 하나로 시선·고개·상체·정지까지 한 번에 봄 |
| 발표연습 앱(녹화형) | 녹화만 되고 분석이 없어서 직접 다시 보며 판단해야 함 | 문제 구간을 시스템이 먼저 찾아서 보여줌 |
| Presentation Trainer | Kinect 같은 특수 장비가 필요하고, 말하는 도중 바로 지적해서 흐름이 끊김 | 일반 카메라로도 되고, 바로 안 끊고 지속시간을 본 뒤 단계적으로만 알려줌 |
| 웹캠 거북목 판별 | 고개 위치 하나만 보고 감지되면 바로 알림이 뜸 | 시간에 따른 움직임 변화까지 봐서 흔들림·정지 같은 패턴도 구분함 |

이렇게 감지 방식(표3)과 사례별 극복(표4)까지 정리하고 나면, "그래서 감지 신호를 구체적으로 뭘로 정할 것인가"로 다음 페이지(03. 감지 신호 선정 및 근거 도출)로 자연스럽게 이어진다.
