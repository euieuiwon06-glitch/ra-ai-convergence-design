움직임 기반 UX 분석 및 UI 디자인 · 프로젝트 정리

Poise

카메라로 발표 자세를 실시간 분석하고 교정 리포트를 주는 발표 습관 코칭 앱
iOS 스타일 웹앱(PWA) 실시간 자세 추정 영상 녹화·다시보기 Supabase 저장 Vercel 배포

본 문서는 움직임(자세) 데이터를 기반으로 사용자의 발표 습관을 분석·시각화하는 프로토타입 「Poise」의 전체 진행 과정, 사용 기술, 화면·기능 구성, 그리고 각 기능을 어떻게 구현했는지를 정리한 것이다.

01프로젝트 개요

주제. 사람의 움직임(관절·자세)을 기반으로 발표 습관을 분석하고, 그 결과를 UX/UI로 풀어내는 프로젝트다. 스마트폰·노트북 카메라만으로 발표 연습 영상을 촬영하면, 자세에서 나타나는 습관 신호를 감지해 교정 리포트와 회차별 개선 추이를 보여준다.

목표

발표를 “평가”하는 도구가 아니라, 혼자 연습하는 사람을 지지적으로 코칭하는 도구. 잘못을 지적하기보다 “다음엔 이렇게 해볼까요?” 톤으로 개선을 유도한다.

타깃

발표·면접·스피치를 혼자 반복 연습하는 학생·직장인. 남에게 보여주기 부담스러운 연습 과정을 앱이 대신 관찰·피드백한다.

감지하는 5가지 습관 신호

시선 회피 고개 움직임 상체 흔들림 발화 멈춤 정상

범위 설정: 본 프로토타입은 움직임(자세) 신호에 집중한다. 음성/입모양 분석은 범위에서 제외했고, ‘발화 멈춤’은 음성이 아니라 전신 움직임이 일정 시간 멈추는 것을 프록시로 감지한다.

04화면 구성 & 플로우

총 12개 화면. 핵심 흐름은 “녹화하여 리포트 받기”이고, 실시간 코칭은 스스로를 보며 교정하는 메타인지용 별도 기능이다.

주 플로우 — 녹화 & 리포트

스플래시→ 온보딩→ 홈→ 카운트다운(3초)→ 녹화(REC)→ 분석 중→ 세션 리포트

보조 플로우

리포트→ 기록(최근 항목 · 통계)· 캘린더 ／ 홈 · 카메라 카드→ 실시간 코칭(별도)
화면설명
01 스플래시로고 + 오로라 마블링 배경, 로딩 진입
02 온보딩“폰을 세로로 1m 거리에서 촬영” 가이드(폰·거리·인물 일러스트)
03 홈인사, AI 비전 카메라 카드(→실시간 코칭), 직전 세션 요약, [연습 시작하기]
04 카운트다운3·2·1 + 시계방향 회전 로딩 링, 자세 안내 패널
05 녹화REC 타이머, 코너 브래킷, 실시간 스켈레톤, [길게 눌러 종료]
06 분석 중진행률(%) + 신호별 분석 단계 표시
07 리포트·요약도넛(습관 분포) + 범례 + 코치 코멘트 + 이전 회차 대비 “달라진 점”
08 리포트·타임라인녹화 다시보기(영상+감지 마커) + 구간 타임라인(에어리어/틱)
09 캘린더월별 연습 기록(감지일 점 표시) + 선택일 카드
10 기록·최근 항목회차 리스트(감지 횟수·최다 습관·전회 대비 증감)
11 기록·통계총 연습·평균 신호·개선률, 회차별 바차트, 가장 잦은 습관
12 실시간 코칭감지 시에만 뜨는 경고 배너 + 소리/일시정지 + 종료(메타인지 연습)

05핵심 기능별 구현 상세

가. 실시간 스켈레톤 오버레이

카메라 영상 위에 관절을 그린다. MoveNet으로 매 프레임 키포인트를 얻어 어깨·팔·머리·골반을 잇고, 셀피처럼 좌우 반전(미러)해 사용자가 자연스럽게 보도록 한다. object-fit: cover 비율에 맞춰 좌표를 매핑하고, 은은한 글로우를 준다. 카메라·모델이 없으면 자동으로 시뮬레이션 스켈레톤으로 대체(데모 모드).

// MoveNet 키포인트 → 캔버스(미러) 매핑
const scale = Math.max(cw/vw, ch/vh);
const map = p => ({ x: cw-(p.x*scale+ox), y: p.y*scale+oy }); // 좌우 반전
EDGES.forEach(([a,b])=> drawLine(map(kps[a]), map(kps[b]))); // 상체 연결선

나. 각도 기반 자세 추정 (5클래스 판정)

딥러닝 분류 대신, 키포인트의 기하(각도·변위)로 습관을 판정한다. 값은 어깨너비로 정규화해 카메라 거리에 무관하게 한다.

신호판정 기준(요지)
고개 움직임양 귀(또는 눈)를 잇는 선의 기울기 각도 > 약 11°
시선 회피코 x가 어깨 중심에서 어깨너비의 20% 이상 벗어남(고개 돌림) + 눈 중앙 대비 보조 판정
상체 흔들림최근 ~0.9초 어깨중심 x의 변동폭 / 어깨너비 > 0.16
발화 멈춤최근 1.5초 전신 움직임 범위 / 어깨너비 < 0.05 (정지 지속)

여러 신호가 겹치면 상체 > 고개 > 시선 > 발화멈춤 우선순위로 하나만 택하고, 최근 ~0.5초 다수결 스무딩으로 떨림을 줄인다.

다. 단계별 경고(알림 피로 방지)

같은 습관이 지속될 때만 단계적으로 알린다. 짧은 순간의 움직임엔 반응하지 않는다.

지속 시간단계피드백
5초주의화면 가장자리 은은한 틴트
10초경고상단 경고 배너 표시 (실시간 코칭 화면 한정)
20초강조강한 틴트 + 경고음 (습관별 8초 쿨다운으로 남발 방지)

라. 세션 집계 — 1.5초 윈도우 다수결

매 프레임을 그대로 세면 노이즈가 크므로, 1.5초 구간 안에서 특정 습관이 70% 이상을 차지할 때만 “1회”로 집계하고 그 시각을 타임라인에 기록한다. 이 타임라인이 이후 리포트·다시보기 마커의 근거가 된다.

마. 세션 리포트 · 통계 (외부 차트 라이브러리 없이)

  • 도넛 — SVG stroke-dasharray 세그먼트로 습관 분포 표현, 가운데 총 감지수
  • 코치 코멘트 — 최다 습관에 맞춘 조언. 한글 받침 유무로 조사(이/가)를 자동 선택
  • “달라진 점” — 직전 회차 대비 증감을 ▼개선 / ▲주의 / –유지로 표기
  • 타임라인 — 12구간 밀도 에어리어 그래프 + 습관별 틱 트랙
  • 통계 — 총 연습·평균 신호·개선률, 회차별 바차트, 가장 잦은 습관 스택바

바. 영상 녹화 (MediaRecorder)

녹화 화면에서 카메라 스트림에 MediaRecorder를 붙여 실제 영상을 저장한다. 브라우저 지원에 따라 webm(vp9/vp8) 또는 mp4를 선택하고, 종료 시 조각을 Blob으로 합쳐 재생용 주소를 만든다.

const mime = ['video/webm;codecs=vp9','video/webm','video/mp4']
  .find(m => MediaRecorder.isTypeSupported(m));
rec = new MediaRecorder(stream, { mimeType: mime });
rec.ondataavailable = e => chunks.push(e.data);
// 종료 시 const blob = new Blob(chunks); const url = URL.createObjectURL(blob);

사. 녹화 다시보기 (영상 ↔ 분석 동기화)

리포트 타임라인 탭에서 실제 녹화 영상을 재생하며, 스크럽바 위에 감지 구간 마커를 겹쳐 보여준다. 마커나 아래 타임라인 블록을 누르면 영상이 그 순간으로 이동하고 어떤 습관이었는지 배지가 뜬다. 영상이 없는 세션(데모/카메라 없음)은 실루엣 목업으로 자동 폴백한다.

아. 실시간 코칭(메타인지)

녹화 플로우와 별개로, 자기 모습을 실시간으로 보며 그 자리에서 자세를 바로잡는 연습 화면. 경고 배너는 문제를 실제로 감지했을 때만 뜨고, 소리 알림·일시정지 컨트롤을 제공한다(리포트는 만들지 않음).

06데이터 · 백엔드 (Supabase)

초기에는 localStorage로 데모 데이터를 다뤘고, 이후 영상·기록을 영구 저장하기 위해 Supabase를 연동했다.

Storage

recordings 버킷에 녹화 영상(webm/mp4) 업로드 → 공개 URL로 재생.

Database (Postgres)

sessions 테이블에 날짜·시간·감지 횟수·클래스별 카운트·타임라인·영상 경로 저장.

저장·불러오기 흐름

녹화 종료→ 영상 → Storage 업로드→ 기록 → DB insert→ 재접속 시 DB에서 로드→ 기록·통계·다시보기 복원

앱 로드 시 저장된 세션을 불러와 데모 데이터에 병합하고, 다시보기는 Storage의 영상 URL로 재생한다. 덕분에 새로고침·재접속·다른 기기에서도 기록과 영상이 유지된다.

검증됨: 라이브에서 14초 녹화 시 2.8MB webm 영상 + 세션 기록(감지 결과 포함)이 실제로 Storage·DB에 저장·조회되는 것을 확인했다.

프로토타입 보안 정책: 현재는 로그인 없는 “공유 데모” 방식(공개 anon 키 + 개방 정책). 실서비스로 가면 Supabase Auth 로그인 + 사용자별 접근 제어(RLS)로 전환한다.

07디자인 시스템 — Aurora Glass

맑고 정제된 케어테크 무드. 페리윙클 액센트 + 오로라 마블링 배경 + 프로스티드 글래스 카드.

형태 원칙. 완전한 알약형(pill) 지양, 정제된 라운드 사각. 데이터 시각화는 평평한 끝의 얇은 트랙·세그먼트·도트 마커 사용. 모션은 진입 fade+rise, 버튼 press 스케일, 카운트다운 시계방향 회전 등 의미 있는 곳에만.

08배포 & 공유

  • Vercel 정적 호스팅(HTTPS). 카메라·마이크는 보안 컨텍스트(HTTPS/localhost)에서만 허용되므로, 실제 녹화 시연을 위해 HTTPS 배포가 필요했다.
  • vercel.json에 cleanUrls와 카메라 권한 허용 헤더(Permissions-Policy: camera=(self)) 설정.
  • 공유 방식 3종 — ① 링크(Vercel URL) ② 단일 HTML 파일(더블클릭, 데모) ③ 로컬 서버. 링크로 공유 시 어느 컴퓨터에서든 열리고, HTTPS이므로 카메라·녹화·저장까지 동작.
라이브 URL: https://poise-deploy.vercel.app — 연습 시작하기 → 녹화 → 리포트 → 타임라인 → 녹화 다시보기, 그리고 재접속 후에도 기록·영상 유지.

09한계 & 향후 계획

현재 한계

  • 자세 판정이 학습 모델이 아닌 휴리스틱(정확도·일반화 한계)
  • ‘발화 멈춤’은 움직임 정지 프록시(실제 음성 미분석)
  • 로그인 없는 공유 데모(사용자 분리 없음)

향후

  • Teachable Machine Pose 모델 학습 → 휴리스틱 대체(연동 지점 마련됨)
  • Supabase Auth 로그인 + 사용자별 저장·통계
  • 음성/입모양 분석 추가, 목표 설정·리마인더
