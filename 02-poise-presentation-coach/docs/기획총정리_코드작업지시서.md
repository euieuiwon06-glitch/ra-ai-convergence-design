# G-1 발표 습관 코칭 — 기획 총정리 (Claude Code 작업 지시서)

이 문서는 프로토타입 제작을 바로 시작할 수 있도록 정리한 최종 스펙 문서. 아이템 선정부터 UI 설계, 실시간 감지 기능까지 전체 포함.

---

## 1. 프로젝트 개요

### 배경
발표자는 스크립트/PPT는 반복 연습하지만, 손 떨림·시선 회피·상체 흔들림 같은 무의식적 습관은 스스로 인지하기 어려움. 녹화해서 봐도 판단 기준이 없어서 개선으로 안 이어짐.

### 타겟
조별과제 발표자, 취준생 면접 준비자, 발표 수업 앞둔 대학생. "평가받는 사람"이 아니라 "혼자 연습하는 사람".

### 차별점
- AI 면접 솔루션(뷰인터 등): 기업의 채용 판단용, 사용자 본인 습관 개선 도구 아님
- 발표연습 앱: 녹화/타이머 기능 위주, AI 분석 없음
- → 연습자 본인을 위한 AI 습관 코치 + 1회성 점수가 아닌 **회차별 개선 추이 비교**가 핵심 소구점

### 검토했던 후보 (참고)
발표/면접 자세 코칭(채택) / 인바디 연동 헬스 코칭(개인맞춤 검증 난이도로 제외) / 안무 싱크 체크 / 악기 연습 자세 코칭(G-2, 비교용으로만 기획 후 최종 제외) / 졸음운전 감시(산업표준화로 차별점 없어 제외)

## 2. 기술 스택 결정

### 판정 방식: Teachable Machine — **Pose Project** (수정됨 ⚠️)

> **변경 사항**: 기존에 Image Project(이미지 분류)로 확정했었으나, 실시간 감지 화면에서 관절 포인트를 선으로 이어 자세를 추정하는 스켈레톤 오버레이가 필요해졌음. Image Project는 키포인트를 출력하지 않기 때문에 **Pose Project(PoseNet 기반)로 전환**해야 함.
>
> Pose Project는 이미지 안에서 관절 키포인트(x, y 좌표)를 자동 추출한 뒤 그 키포인트 배열을 입력으로 분류 모델을 학습하는 방식. 데이터 수집 방식(사진/영상 촬영)은 기존과 동일하게 쓸 수 있고, TM 웹 UI에서 프로젝트 타입만 Pose로 바꾸면 됨. 추가로 얻는 이점: 학습된 모델이 예측할 때 키포인트 좌표도 같이 반환하기 때문에, 그 좌표를 캔버스에 선으로 이어 그리면 스켈레톤 오버레이 구현 가능 (별도 pose estimation 라이브러리 안 붙여도 됨).

### 판정 로직: 1.5초 윈도우 다수결 (세션 카운트용, 유지)
- 1.5초 윈도우 동안 여러 프레임을 모아 특정 클래스 확신도 70% 이상이면 카운트 1회 증가
- 발화 멈춤 클래스만 2초 기준 (짧은 숨 고르기와 구분)
- 이 로직은 **세션 종료 후 리포트에 들어갈 "총 발생 횟수" 집계용**으로 그대로 유지

### 실시간 경고 로직: 지속시간 기반 단계적 알림 (신규 — 자세코치 프로젝트 반영)
자세코치(PostureCare) 프로젝트에서 쓴 2단계 타이밍 구조를 그대로 적용:

| 단계 | 지속 시간 | 반응 |
|---|---|---|
| 1단계 확인 | 문제 자세(정상 외 클래스)가 **5초** 이상 지속 | 화면 상단 스켈레톤/테두리 색상 변화로 조용히 표시 (아직 팝업 없음) |
| 2단계 경고 | **10초** 이상 지속 | 상단에 팝업 배너로 경고 문구 표시 (예: "시선이 계속 한쪽으로 쏠려 있어요") |
| 3단계 강한 경고 | **20초** 이상 지속 | 팝업 유지 + 경고 신호음 추가 |

**경고 피로(alarm fatigue) 고려**: 웹캠 기반 실시간 자세 교정 관련 선행 연구에서, 반복적인 경고 피드백이 사용자 경험을 저해하고 장기 사용 의도를 낮춘다는 결과가 있음. 그래서 이 프로젝트는 처음부터 팝업을 띄우지 않고 단계적으로 올리는 구조로 설계한 것 — 이 설계 의도를 유지할 것. 같은 클래스로 재차 경고가 뜰 때는 쿨다운(예: 한번 경고 뜨고 나면 최소 8초는 재알림 안 함) 적용 권장.

### 기존 설계 변경 사항 정리 ⚠️
> 원래 "연습 진행 화면"은 **"UI 개입 최소화, 실시간 알림 없음 (몰입 방해 방지)"**로 정의되어 있었음. 이번 요청으로 이 결정을 뒤집고, 실시간 스켈레톤 오버레이 + 단계적 경고 팝업을 진행 화면에 넣기로 변경함. 세션 종료 후 리포트/회차 비교 화면은 기존 설계 그대로 유지.

### 구현 형태: PWA (모바일 웹앱, 유지)
- 폰 브라우저 → "홈 화면에 추가"로 아이콘 실행
- 네이티브 앱(TFLite 변환 등)은 스코프 초과로 제외

### 음성 분석: 이번 스코프 제외 (유지)
발표 톤(음성) 분석은 별개 기술 트랙이라 이번엔 제외, 기획안엔 "향후 확장 아이디어"로만 언급.

## 3. 클래스 정의 (5개, 확정)

| 클래스 | 설명 | 판단 기준 |
|---|---|---|
| 정상 | 평상시 발표 자세/발화 | — |
| 시선 회피 | 정면 대비 시선/고개 좌우 이탈 | 1.5초 윈도우 내 확신도 70% 이상 |
| 고개 움직임 | 과도한 끄덕임 + 고개 숙임 + 고개 젖힘/치켜듦 (통합) | 1.5초 윈도우 내 확신도 70% 이상 |
| 상체 흔들림 | 몸통/어깨 좌우 흔들림 | 1.5초 윈도우 내 확신도 70% 이상 |
| 발화 멈춤 | 입이 벌어진 채 정지 (말 끊김) | 정지 상태 2초 이상 지속 |

(손 떨림, 정지 경직 클래스는 검토했으나 최종 제외/대체됨)

## 4. 데이터 수집 계획

### 클래스별 목표 이미지 수 (Pose Project 기준, 촬영 방식 동일)

| 클래스 | 목표 수량 | 비고 |
|---|---|---|
| 정상 | 150~200장 | 오분류 방지 위해 가장 많이 확보 |
| 시선 회피 | 100~120장 | |
| 고개 움직임 | 100~120장 | 끄덕임/숙임/젖힘 세 동작 골고루 |
| 상체 흔들림 | 100~120장 | |
| 발화 멈춤 | 100~120장 | |

우선 클래스당 60~80장으로 1차 학습 → 오분류 나는 클래스만 추가 촬영 권장.

### 촬영 프로토콜
- 거치: 폰 세로, 1m 거리, 눈높이~약간 아래
- 배경: 최소 2가지 이상 (단색 벽 + 실제 발표 환경)
- 인원: 가능하면 2~3명 (여의치 않으면 본인 위주 + 각도/조명 변주)
- 각도: 정면 위주 + 좌우로 살짝 튼 각도 섞기
- 클립: 클래스당 20~30초 영상 3~4개 → 초당 1~2프레임 추출

### 프레임 추출
- TM 웹캠 캡처 기능으로 직접 촬영, 또는
- 영상 촬영 후 `ffmpeg -i clip.mp4 -vf fps=2 frame_%03d.jpg` 로 추출

### 라벨링
TM은 폴더=클래스라 별도 라벨링 툴 불필요. 촬영 시 폴더명을 클래스명으로 저장.

## 5. 전체 UX 플로우

```
1. 온보딩 (최초 1회)
   ├ 앱 소개
   └ 거치 가이드 ("폰을 세로로, 1m 거리")
        ↓
2. 대기 화면 (홈)
   ├ 카메라 프리뷰
   ├ 직전 세션 요약 카드
   └ [연습 시작] 버튼
        ↓
3. 카메라 권한 / 거치 확인
   └ 카운트다운 3초 → 자동 시작
        ↓
4. 실시간 감지 진행 화면 ★ 신규
   ├ 셀카모드 카메라 프리뷰
   ├ 관절 키포인트를 선으로 이은 스켈레톤 오버레이 (실시간)
   ├ 경과 시간 타이머
   ├ 문제 자세 5초 지속 → 스켈레톤/테두리 색상 변화
   ├ 문제 자세 10초 지속 → 상단 팝업 경고 배너
   ├ 문제 자세 20초 지속 → 팝업 + 경고음
   └ [종료] 버튼 (롱프레스 or 확인모달)
        ↓
5. 종료 확인 → 분석중 로딩
        ↓
6. 세션 리포트 화면
   ├ 클래스별 발생 횟수 (1.5초 윈도우 다수결 집계)
   ├ 타임라인 바 (발생 구간 시각화)
   └ [회차 비교 보기] / [다시 연습]
        ↓
7. 회차 비교 화면
   ├ 최근 N회차 라인 그래프
   ├ 개선 코멘트
   └ 재연습 제안 카드
```

## 6. 화면별 상세 요구사항

### 6-1. 대기 화면
- 카메라 프리뷰, 직전 세션 요약 카드, [연습 시작] 버튼

### 6-2. 카메라 권한/거치 안내
- 권한 요청 + "폰을 세로로, 1m 거리" 안내 문구
- 카운트다운 3, 2, 1 → 자동 전환

### 6-3. 실시간 감지 진행 화면 (신규, 핵심)
**레이아웃**
- 화면 전체 = 셀카모드 카메라 프리뷰
- 프리뷰 위에 캔버스 오버레이 (관절 키포인트 + 연결선)
- 상단바: 경과 시간 타이머, 상태 인디케이터(정상/주의)
- 하단: [종료] 버튼

**스켈레톤 오버레이**
- TM Pose 모델이 반환하는 키포인트 좌표(코, 눈, 귀, 어깨, 팔꿈치, 손목, 엉덩이 등)를 캔버스에 점 + 선으로 실시간 렌더링
- 정상 상태: 민트/기본색 선
- 문제 자세 감지(5초 이상): 선 색상을 경고색(예: 주황)으로 전환

**경고 팝업 (10초 이상 지속 시)**
- 상단에서 슬라이드 다운되는 배너
- 문구는 클래스별로 다르게: "시선이 계속 한쪽으로 쏠려 있어요" / "고개가 많이 움직이고 있어요" / "몸이 흔들리고 있어요" / "말이 잠시 끊긴 것 같아요"
- 자동 5초 후 사라짐 or 자세 정상 복귀 시 즉시 사라짐

**경고음 (20초 이상 지속 시)**
- 짧은 알림음 1회 (반복 재생 X — 경고 피로 방지)
- 쿨다운: 같은 클래스 재알림까지 최소 8초 간격

### 6-4. 세션 리포트 화면
- 클래스별 발생 횟수 카드/리스트
- 타임라인 바 (탭하면 해당 시점 상세 툴팁)
- [회차 비교 보기] / [다시 연습]

### 6-5. 회차 비교 화면
- 최근 N회차 라인 그래프
- 개선 코멘트, 재연습 제안 카드

## 7. 상태 다이어그램

대기 → 카메라권한요청 → 카운트다운 → 감지중(정상/주의/경고) → 종료확인 → 분석중(로딩) → 리포트표시 → 비교화면

"감지중" 상태는 내부적으로 3단계 세분화: 정상 / 주의(5초~) / 경고(10초~) / 강한경고(20초~)

## 8. 필요 아이콘 목록

**내비게이션**: 뒤로가기, 홈, 설정, 닫기(X)

**카메라/촬영**: 카메라 렌즈, 시작(▶), 종료(■), 타이머, 폰 스탠드 거치 가이드

**클래스별 신호 아이콘**
- 시선 회피 → 눈
- 고개 움직임 → 고개/회전 화살표
- 상체 흔들림 → 좌우 흔들림 화살표
- 발화 멈춤 → 마이크 뮤트 or 입 모양
- 정상 → 체크마크

**실시간 감지 화면 전용**
- 경고 배너 아이콘 (경고 삼각형 or 느낌표)
- 스피커/음소거 토글 (경고음 on/off 옵션)
- 상태 인디케이터 점(정상=민트, 주의=노랑, 경고=주황/빨강)

**리포트/비교**: 타임라인 바, 라인 그래프, 상승/하강 화살표, 요약 카드

**기타**: 재연습(↻), 공유(선택), 알림 뱃지

## 10. 아직 논의 안 된 것

- 클래스별 정확한 촬영 개수/각도 세부 프로토콜 최종 확정
- 발화 멈춤 판정 시간(2초) 및 실시간 경고 타이밍(5/10/20초)이 적절한지 실사용 테스트로 검증 필요
- 컬러 톤 최종 확정
- 경고음 소리 종류/볼륨, 무음 모드 지원 여부
- 8단계 Figma UI 디자인 — 아직 미착수
- 9단계 AI-UI 연동 구현, 10단계 사용성 평가 — 미착수

## 11. Claude Code 구현 시 참고사항
