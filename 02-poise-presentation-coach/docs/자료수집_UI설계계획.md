# G-1 발표 습관 코칭 — 자료수집 계획 + UI 디자인 설계 계획

## 자료수집 계획

TM 이미지 모델이니까 "클립"보다 정확히는 **프레임(이미지)**이 학습 단위. 영상을 찍고 거기서 프레임 뽑아서 업로드하는 방식으로 가면 됨.

### 클래스별 필요량

| 클래스 | 목표 이미지 수 | 이유 |
|---|---|---|
| 정상 | 150~200장 | 정상 클래스가 다른 클래스와 오분류 많이 나는 게 이미 확인된 이슈라 (자세 감지 프로젝트에서도 동일 현상), 다양성 확보 차원에서 제일 많이 |
| 시선 회피 | 100~120장 | |
| 고개 움직임 | 100~120장 (끄덕임/숙임/젖힘 세 동작 골고루 섞어서) | |
| 상체 흔들림 | 100~120장 | |
| 발화 멈춤 | 100~120장 (입 벌린 정지 상태) | |

총 550~680장 정도. 처음부터 다 채우지 말고 우선 클래스당 60~80장으로 1차 학습 → 오분류 나는 클래스만 추가 촬영하는 식으로 가는 게 효율적.

### 촬영 프로토콜

- **거치**: 폰 세로 거치, 1m 거리, 눈높이 or 약간 아래
- **배경**: 최소 2가지 이상 (단색 벽 + 실제 발표 환경 느낌) — 배경 단일하면 실사용 환경에서 오분류 커짐
- **촬영 인원**: 가능하면 본인 포함 2~3명. 1인 데이터만 학습하면 다른 사람 얼굴/체형에서 정확도 떨어질 가능성 높음 (시간 없으면 최소 본인 1인 + 각도/조명 변주로 보완)
- **각도**: 완전 정면 위주 + 좌우로 살짝 틀어진 각도 섞기 (실제로 폰 앞에서 완벽하게 정자세로 안 서니까)
- **클립 길이**: 클래스당 20~30초짜리 영상 3~4개 촬영 → 초당 1~2프레임 추출

### 프레임 추출 방법

영상 찍은 다음 프레임 뽑는 게 제일 시간 절약됨. 방법 두 가지:

1. **TM 웹캠 기능으로 직접 촬영**: Teachable Machine이 웹캠에서 홀드하고 있는 동안 자동으로 여러 프레임 캡처해줌. 가장 간단.
2. **폰으로 찍은 영상에서 추출**: ffmpeg로 `ffmpeg -i clip.mp4 -vf fps=2 frame_%03d.jpg` 하면 초당 2프레임씩 뽑힘.

### 라벨링

TM은 폴더 = 클래스라서 별도 라벨링 툴 필요 없음. 촬영할 때부터 폴더명을 클래스명으로 맞춰서 저장해두면 업로드만 하면 끝.

## UI 디자인 설계 계획


### 필요 아이콘 목록

**공통/내비게이션**
- 뒤로가기, 홈, 설정(톱니바퀴), 닫기(X)

**카메라/촬영 관련**
- 카메라 렌즈, 촬영 시작(재생 ▶), 종료(정지 ■), 타이머/시계, 거치 가이드용 폰 스탠드 아이콘

**클래스별 신호 아이콘** (리포트 화면에서 각 클래스 구분용)
- 시선 회피 → 눈
- 고개 움직임 → 고개/화살표 회전
- 상체 흔들림 → 좌우 흔들림 화살표
- 발화 멈춤 → 마이크 뮤트 or 입 모양
- 정상 → 체크마크

**리포트/비교 화면**
- 막대/타임라인 바, 라인 그래프, 화살표(상승/하강 개선 표시), 카드형 요약 아이콘

**기타**
- 재연습(리플레이 ↻), 공유(선택사항), 알림 뱃지



### 화면 전환 계획 (페이지 순서)_변동가능

```
1. 온보딩 (최초 1회)
   ├ 앱 소개 1~2장
   └ 거치 가이드 ("폰을 세로로, 1m 거리")
        ↓
2. 대기 화면 (홈)
   ├ 카메라 프리뷰
   ├ 직전 세션 요약 카드
   └ [연습 시작] 버튼
        ↓
3. 카메라 권한/거치 확인 (모달 or 별도 화면)
   └ 카운트다운 3초 → 자동 촬영 시작
        ↓
4. 연습 진행 화면
   ├ 카메라 프리뷰만 (UI 최소화, 실시간 알림 없음)
   ├ 경과 시간 타이머
   └ [종료] 버튼 (오조작 방지 위해 롱프레스 or 재확인)
        ↓
5. 종료 확인 모달 → 로딩(분석 중)
        ↓
6. 세션 리포트 화면
   ├ 클래스별 발생 횟수 (카드/리스트)
   ├ 타임라인 바 (발생 구간 시각화)
   └ [회차 비교 보기] / [다시 연습] 버튼
        ↓
7. 회차 비교 화면
   ├ 최근 N회차 라인 그래프
   ├ 개선 코멘트
   └ [재연습 제안] 카드
        ↓ (뒤로가기)
   대기 화면으로 복귀
```

### 상태 다이어그램

E트랙은 6개 상태였는데, G-1은 답변 분기가 없어서 더 단순하게 4단계로 정리:

- 대기
- 촬영중 (권한요청 → 카운트다운 → 녹화)
- 분석중 (로딩)
- 리포트표시

### 인터랙션 설계

- [연습 시작] 클릭 → 카운트다운 3, 2, 1 → 자동 전환
- 종료 버튼은 실수로 안 눌리게 롱프레스 or 확인 모달
- 리포트 화면 → 회차 비교는 스와이프 or 탭 전환
- 타임라인 바 특정 구간 탭하면 "이 시점에 시선 회피 3회" 같은 툴팁
