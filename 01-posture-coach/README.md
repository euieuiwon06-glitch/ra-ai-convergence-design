# 01 · 자세 코치 (PostureCoach)

**컴퓨터 비전 기반 UX 분석 및 UI 디자인 — 자세 트랙**

온라인 강의·과제 중에 흐트러진 자세를 웹캠으로 감지하고, 학습 흐름을 끊지 않는 방식으로 알려주는 Windows 데스크톱 앱입니다.

- 🖥️ **웹 프로토타입:** https://euieuiwon06-glitch.github.io/ra-ai-convergence-design/01-posture-coach/prototype/ (웹캠 권한 필요)
- 📦 **Windows 실행 파일:** [Releases](https://github.com/euieuiwon06-glitch/ra-ai-convergence-design/releases)의 `자세코치-PostureCoach.exe` (설치 없이 실행, 첫 실행 시 SmartScreen에서 "추가 정보 → 실행")

| 항목 | 내용 |
|---|---|
| 타깃 | 노트북으로 장시간 학습하는 대학생 · 온라인 학습자 |
| 자세 클래스 | Normal / Slouch / Lean / Chin / Away |
| 기술 | Teachable Machine Pose, TensorFlow.js, Vanilla JS, Web Audio API, Electron |
| 데이터 | 5클래스 280장 직접 촬영 |

## 문제 정의

장시간 온라인 학습자는 자세가 무너지고 집중이 떨어져도 스스로 알아차리기 어렵고, 기존 학습 UI는 사용자의 신체 상태를 전혀 모릅니다.
선행 연구(문수정·이윤, 2025)에서는 실시간 경고음이 바른 자세 유지 시간은 늘렸지만 **경고음 피로**를 일으켰습니다. 그래서 핵심 설계 과제를 "언제, 얼마나 절제해서 알릴 것인가"로 잡았습니다.

## 설계

**피드백 단계 (프로토타입 기준, 배포 기준은 5분)**

| 지속 시간 | 반응 | 의도 |
|---|---|---|
| 5초 미만 | 없음 | 순간 오분류 필터링 |
| 5초 | 자세 확정 (화면 반응 없음) | 스스로 고칠 시간 확보 |
| 10초 | 화면 상단 중앙 팝업 | 시선을 웹캠 쪽으로 올리도록 유도 |
| 20초 | 팝업 + 경고음 | 팝업을 무시한 경우에만 소리로 개입 |
| Normal 복귀 | 즉시 해제 | 부담 해소 |

클래스별 문구는 "허리 펴세요 / 고개 드세요 / 자세를 바로잡아주세요"이고, Away는 경고가 아닌 안내 톤("자리를 비우셨어요")으로 소리 없이 표시합니다.

## 구현

- 300ms 주기 추론 → **최근 6프레임 다수결 스무딩** → 지속 시간 누적 → 임계값 판정
- 창을 최소화해도 감지가 멈추지 않도록 `requestAnimationFrame` 대신 `setInterval` 사용
- 경고음은 음원 파일 없이 Web Audio 오실레이터로 880Hz 사인파를 합성
- 세션 종료 시 바른 자세 유지율과 클래스별 점유율 리포트

### 웹앱 → 데스크톱 앱 전환

브라우저 알림은 Windows에서 우측 하단에 고정되어 위치를 바꿀 수 없습니다. "팝업을 웹캠 바로 아래에 띄운다"는 설계 근거를 지키려고 Electron으로 전환했고, 테두리 없고 포커스를 빼앗지 않는 항상 위 알림창을 화면 상단 중앙에 직접 배치했습니다.
앱이 활성 상태면 인앱 팝업을, 다른 프로그램을 쓰는 중이면 이 알림창을 띄웁니다.

> 배운 점: 플랫폼 선택은 기술 편의가 아니라 UX 요구사항에서 역산해야 한다.

## 모델 검증 결과

| 클래스 | 평균 신뢰도 | 관찰 |
|---|---|---|
| Slouch | 99.3% | 가장 안정적 |
| Lean | 97.8% | Normal과 경계가 모호 |
| Chin | 97.1% | 수치보다 체감 정확도가 낮음 (팔 각도 의존) |
| Normal | 91.2% | 편차 최대 (78~100%), 작은 움직임에도 흔들림 |

실사용 테스트에서는 Normal이 Slouch·Chin으로 오분류되는 경우가 많았습니다. 원인은 학습 데이터가 한 사람, 한 화각에 치우친 것으로 판단했습니다. 스무딩과 지속 시간 기준 덕분에 순간 오분류가 곧바로 잘못된 경고로 이어지지는 않았습니다.

## 폴더

```
prototype/          웹앱(index.html · style.css · app.js) + Electron 래퍼(electron/) + 아이콘(build/)
docs/               기획안 1-10단계 종합 (md · pdf), 6단계 모델 학습·검증 결과

```

### 실행

```bash
cd prototype
npm install
npm start        # Electron 앱 실행
npm run dist     # Windows 포터블 exe 빌드
```

## 한계 · 후속 과제

1. 여러 사람, 여러 화각으로 Normal 데이터 재수집 후 재학습 (교수님 피드백: 클래스를 3개 정도로 줄여 구분 정확도 우선)
2. 실제 학습 세션에서 알림 적절성·방해도 사용성 평가
3. 시간 기준을 배포 기준(5분)으로 전환 후 재검증
4. 코드 서명으로 SmartScreen 경고 제거
